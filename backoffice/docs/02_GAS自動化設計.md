# 02. Google Apps Script 自動化設計

対象：`GR_共通管理台帳` にコンテナバインドする GAS（ソースは `gas/`）。
社内台帳専用。**クライアントのデータには触れない**（クライアント向け自動化はクライアント所有の別プロジェクトで構築）。

## 1. 自動化の一覧

| 機能 | 関数 | 起動 | 内容 |
|---|---|---|---|
| 台帳セットアップ | `setupLedgers()` | メニュー（初回・定義変更時） | 全シート・見出し・入力規則・書式・数式・条件付き書式を作成。冪等（既存データは消さない） |
| 入力規則の再適用 | `reapplyValidations()` | メニュー | 選択肢マスタの編集を全台帳に反映 |
| 案件フォルダ作成 | `processPendingFolders()` | 10分ごと＋メニュー | 案件マスタで☑かつURL空の行に、フォルダ階層＋テンプレート3点を作成し、`{{案件ID}}` 等を差し込み、URLを書き戻す |
| 日次チェック | `dailyCheck()` | 毎朝8時 | 再確認期限切れ・未入金・見込み放置・報酬開示漏れを1通にまとめて管理者に通知。古いログを削除 |
| 診断テンプレート生成 | `buildDiagnosisTemplate()` | メニュー（初回のみ） | `TPL_ツール活用診断` を作成 |
| トリガー管理 | `installTriggers()` / `removeTriggers()` | メニュー | 既存を削除してから張り直し（二重登録防止） |

ヒアリングシート・提案書のテンプレート（Googleドキュメント）は、`templates/02`・`templates/04` の内容を手動で貼り付けて作成し、IDを設定シートに入力する（見出しスタイル適用のため手動を推奨）。

## 2. 非機能要件への対応

| 要件 | 実装 |
|---|---|
| クラウド自動実行 | 時間主導トリガー（PCの電源と無関係） |
| 管理画面からの設定変更 | 「設定」「選択肢マスタ」シート。コードにIDや宛先を書かない |
| 重複処理の防止 | `LockService`、URL列による処理済み判定、同名フォルダ／同名ファイルの再利用 |
| 実行ログ・エラーログ | `実行ログ` シートに全実行を記録（OK/WARN/ERROR）、保持期間経過で自動削除 |
| 障害通知 | 例外時に `NOTIFY_EMAIL` へメール。1件の失敗で他案件を止めない |
| 認証情報の管理 | 台帳・フォルダに認証情報を保存しない。将来外部APIを使う場合は `PropertiesService`（スクリプトプロパティ）に保存 |
| 最小権限 | `appsscript.json` でスコープを明示（下表） |
| テスト／本番分離 | テスト用台帳＋テスト用フォルダで検証 → 本番台帳を別ファイルで作成。`ENV` で通知件名を区別 |

### OAuth スコープ

| スコープ | 用途 |
|---|---|
| spreadsheets | 台帳の読み書き、診断テンプレートの新規作成 |
| drive | 案件フォルダ作成、テンプレートのコピー |
| documents | コピーしたドキュメントへの差し込み |
| script.send_mail | 管理者への通知メール |
| script.scriptapp | トリガーの設定 |
| script.container.ui | カスタムメニュー |
| userinfo.email | ログの実行者記録 |

> `drive` は広い権限のため、テンプレートを本スクリプトで作成する運用にすれば `drive.file` へ縮小可能（将来検討）。

## 3. テスト計画（テスト環境）

| # | テスト | 期待結果 |
|---|---|---|
| 1 | 空のスプレッドシートで `setupLedgers()` | 9シート作成、プルダウン・数式が動作、パートナー10件が「未調査」で投入 |
| 2 | 再度 `setupLedgers()` | データ・選択肢が重複しない、WARN なし |
| 3 | 案件マスタにダミー `C900_テスト株式会社` を入れ☑ → メニュー実行 | フォルダ10個・テンプレ3点、Doc内の `{{案件ID}}` が置換、URL書き戻し |
| 4 | #3 の直後に再実行 | 何も作られない（重複防止） |
| 5 | URL を消して再実行 | 既存フォルダを再利用、ファイルは重複しない |
| 6 | `CASE_ROOT_FOLDER_ID` を空にして実行 | ERROR ログ＋通知メール（[TEST]） |
| 7 | 紹介案件に入金予定日=昨日・入金日空 → `dailyCheck()` | [未入金] を含む通知1通、行が赤 |
| 8 | 契約日を入れ報酬開示未チェック | [開示漏れ] 通知、行が黄 |
| 9 | 案件収益管理にダミー明細 | 案件別サマリーの区分別・合計・時間単価が正しい |

## 4. 運用マニュアル（概要）

**新規案件の開始**
1. 案件マスタに 案件ID・クライアント名・案件名・担当者 を入力
2. 「フォルダ作成」に☑ → 10分以内（またはメニュー実行）でフォルダURLが入る
3. `01_ヒアリング` のヒアリングシートで初回ヒアリング

**新規ツールを提案するとき**
1. パートナー管理台帳で該当サービスを確認（登録状況・最終確認日・掲載可否）
2. 未登録なら「調査済・未登録」にし、登録要否を判断（架空リンクは作らない）
3. 提案書の比較表・開示文を記入し、提出前チェックを実施
4. 紹介案件管理台帳に「見込み」で登録、報酬開示済みに☑

**紹介報酬の進捗**：見込み → 成果発生 → 承認済み → 入金済み（入金時は案件収益管理にも明細を追加）

**月次**：案件別サマリーで売上・時間単価を確認／実行ログの ERROR を確認

**トラブル時**：通知メールの内容と実行ログを確認 → 設定シートのID・宛先を見直し → メニューから再実行（重複作成はされない）
